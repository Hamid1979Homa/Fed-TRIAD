# Fed-TRIAD — code and results

Code, raw results and figures for the numerical study (Section 6) and the numerical checks of the proofs in the manuscript

> *Fed-TRIAD: Input-Dependent Three-Path Personalized Federated Learning with Adaptive Reclustering: Correlated-Error Routing, Convergence under Partition Changes, and a Lower Bound for Static Clustering.*

All data are synthetic and generated by the code; no external dataset is used.

## Quick start

Requirements: Python 3.12 or newer (the pinned versions in `requirements.txt` need it) and a bash shell (Linux, macOS, WSL, or Git Bash on Windows; on plain Windows run the five commands of the table below one by one).

```bash
python -m venv venv && source venv/bin/activate     # Windows: venv\Scripts\activate
pip install -r requirements.txt
bash run_all.sh            # about 1–2 hours on 2 cores; set JOBS=8 to use more cores
```

`run_all.sh` runs five steps, each of which can also be run on its own from `src/`:

| Step | Command (in `src/`) | What it does |
|---|---|---|
| 1 | `python theory_checks.py` | 16 numerical checks of the algebra in the proofs; each check has a control that must fail |
| 2 | `python test_sim.py ../reference/drift_m12_first_study_seeds1-5.npy` | checks of the simulator: it reproduces the first study (relative tolerance 1e-4 on the excess risk averaged over the last 20 rounds), Ditto with λ = 0 equals local SGD, the shift-size parameter behaves as specified; every check is paired with a planted fault that must make it fail |
| 3 | `python run_sweep.py --out ../results --jobs 2` | main study and sensitivity study: 23 settings × 10 seeds (resumable; one file per run in `results/runs/`, one file per setting in `results/`). It recomputes everything and overwrites the stored `results/*.npy` |
| 4 | `python analyze.py ../results ../outputs` | writes `outputs/numbers.json` (every number in Section 6) and the figures |
| 5 | `python check_against_reference.py ../outputs/numbers.json ../reference/numbers_reference.json` | compares the recomputed numbers with the reference numbers that the paper was written from (see "Reproducibility") |

A successful run ends with `MATCH: every count, decision and label equals the reference of the paper.`

## Repository layout

```
src/fedtriad_sim.py              Algorithms 1–3, data model, all methods, Theorem 2/5 diagnostics
src/run_sweep.py                 the 23 settings (main study + sensitivity study) and the seeds
src/analyze.py                   summaries, paired decision rule, figures
src/test_sim.py                  simulator checks with planted faults
src/theory_checks.py             numerical checks of the proofs with failure controls
src/check_against_reference.py   comparison of recomputed numbers with the reference numbers
results/<setting>.npy            raw results (10 seeds) for each setting; <setting>.cfg.json = exact configuration
outputs/numbers.json             every number reported in Section 6 (as produced by step 4)
outputs/fig*.png                 Figures 2–6
reference/numbers_reference.json copy of outputs/numbers.json that the paper was written from (used by step 5)
reference/drift_m12_first_study_seeds1-5.*   results of the first study (seeds 1–5), used by test_sim.py
```

`results/*.npy` are Python dictionaries saved with NumPy; load them with `np.load(path, allow_pickle=True).item()`. Only load pickled files from a source you trust.

## Settings

Base setting: N = 30 clients, T = 200 rounds, concept shift at round 100 for s = 8 clients, κ = 0.6 (concept separation), ω = 0.6 (client deviation), m = 12 participants per round, 60 path and 30 gate samples per client, hysteresis τ_imp = 0.02, re-clustering window W = 10. Seeds 1–10.

| Group | Settings |
|---|---|
| Main study | `drift_m12` (base), `drift_m30` (full participation), `scarce_m12` (25/15 samples, noise 1.0, κ = ω = 0.3) |
| κ × ω | κ ∈ {0.3, 0.6, 1.0} × ω ∈ {0.3, 0.6, 1.0} (`kw_k*_w*`) |
| Shifted clients | s ∈ {0, 4, 8, 12} (`s0`, `s4`, base, `s12`); s = 0 is the no-drift control |
| Hysteresis | τ_imp ∈ {0, 0.01, 0.02, 0.05, 0.10} (`tau*`) |
| Window | W ∈ {5, 10, 20} (`W5`, base, `W20`) |
| Participation | m ∈ {6, 12, 30} (`m6`, base, `drift_m30`) |
| Data per client | n_path ∈ {30, 60, 120}, n_gate = n_path/2 (`n30`, base, `n120`) |

Methods: Local, FedAvg, cluster path (static / adaptive), personal/global with constant weights (APFL-style), personal/global with an input gate (Flow-style re-implementation), personal/cluster with an input gate, Ditto (λ ∈ {0.1, 1, 10} chosen on the held-out gate split), three-path ablations, Fed-TRIAD, and Fed-TRIAD with the oracle partition.

## Reporting rule (fixed before the sensitivity runs)

Metric: excess risk averaged over the last 20 rounds. In each setting, the strongest competitor is the non-oracle, non-ablation method with the lowest mean. Fed-TRIAD is called *better* (or *worse*) than a method only if its excess risk is lower (or higher) in at least 8 of the 10 seeds; otherwise the result is *no consistent difference*. All settings are reported.

## Reproducibility

Everything is deterministic given the seed. What can differ between machines is floating-point rounding, so the stored results are bit-identical only on the software and hardware that produced them.

**Tested (Linux x86-64, Python 3.13, the versions in `requirements.txt`).** A fresh clone of this repository passes steps 1 and 2. Three settings (`drift_m12`, `scarce_m12`, `tau0.0`; 30 runs) were recomputed from scratch with step 3 and all 1260 stored arrays were bit-identical; the same holds for `s0` when Python's `spawn` start method (the Windows default) is forced.

**Other CPUs (emulated).** The CPU was changed by selecting other OpenBLAS kernels (Haswell; Nehalem with AVX, AVX2, AVX-512 and FMA switched off in NumPy) and four settings (`drift_m12`, `scarce_m12`, `kw_k0.3_w1.0`, `s0`; 40 runs) were recomputed:

* no run was bit-identical to the stored one, as expected;
* all discrete outputs (number of clusters, ARI, number and rounds of re-clusterings, Ditto's λ) were identical in all 40 runs;
* all 819 counts, decisions and labels in `numbers.json` (every *better / worse / no consistent difference* verdict, the number of seeds behind each, the strongest competitor) were identical;
* in the base setting, the excess risk averaged over the last 20 rounds differed by at most 2·10⁻⁷ (relative) over 10 seeds and 12 methods; this is why step 2 uses a relative tolerance of 1e-4 (a 10⁻³ change of κ changes the same quantity by up to 5·10⁻²);
* continuous statistics can differ more in the data-scarce setting `scarce_m12`, where the gate is fitted on 15 samples per client and rounding differences are amplified: of 456 aggregated means, 447 agreed within 0.1 % and the largest difference was 1.1 % (the worst-client statistic of one method); some per-seed values differ by up to 10 % (quantities close to zero, such as the re-clustering changes below, differ more in relative terms). A table cell of Section 6 can therefore change in its last printed digit on another machine; no conclusion changes;
* one count in Section 6.3 sits close to a rounding threshold: in `scarce_m12`, 9 of the 17 re-clusterings that did not coincide with the shift are followed by an increase of the excess risk, and one of these changes has size 5·10⁻⁶, so on other hardware the count can read 8 or 10 (it read 9 in the emulated-CPU runs). In the two drift settings the corresponding count is 0 of 32, with every change below −2.8·10⁻⁴, which is robust.

Step 5 therefore requires every count, decision and label to be **equal**, reports how closely the continuous values agree, and fails on a continuous value only if an aggregated mean differs by more than 10 %.

**Not tested.** Python 3.11 or older, other versions of NumPy, SciPy, scikit-learn or matplotlib (scikit-learn's k-means can change between versions, which can change the numbers), BLAS libraries other than OpenBLAS (MKL, Accelerate), native Windows, macOS or ARM machines, and a complete run of all 230 simulations on a second machine. If step 5 reports a mismatch, compare your library versions with `requirements.txt` first.
